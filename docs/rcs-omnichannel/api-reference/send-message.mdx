# Send RCS Message

Send an RCS message using a pre-approved template. Supports rich media, suggested actions, and automatic SMS fallback for non-RCS capable devices.

<TryItBanner method="POST" endpoint="/v2/accounts/{sid}/messages" />

<RegionalUrls path="/v2/accounts/{account_sid}/messages" host="api" />

## Request Parameters

| Parameter         | Required  | Type   | Description |
|-------------------|-----------|--------|-------------|
| `custom_data`     | Optional  | String | Custom metadata passed through to status callbacks |
| `status_callback` | Optional  | String | Webhook URL for delivery receipt events |
| `rcs`             | Mandatory | Object | RCS channel configuration (see below) |

### RCS Object

| Parameter  | Required  | Type   | Description |
|------------|-----------|--------|-------------|
| `from`     | Mandatory | String | BotID for sending (provided by Exotel) |
| `to`       | Mandatory | String | Recipient phone in E.164 format (e.g., `+919888888888`) |
| `content`  | Mandatory | Object | Template message content |
| `fallback` | Optional  | Object | SMS fallback configuration |

### Content Object

| Parameter   | Required  | Type   | Description |
|-------------|-----------|--------|-------------|
| `name`      | Mandatory | String | Pre-approved template identifier |
| `variables` | Mandatory | Object | Key-value pairs for template variable substitution |

```json
{
  "name": "welcome_template",
  "variables": {
    "customer_name": "Rahul",
    "order_id": "ORD-12345"
  }
}
```

### Fallback Object

| Parameter     | Required  | Type   | Description |
|---------------|-----------|--------|-------------|
| `sms.from`    | Mandatory | String | SMS sender ID |
| `sms.content` | Mandatory | String | Fallback SMS text (sent if RCS delivery fails) |

## HTTP Status Codes

| Code | Description |
|------|-------------|
| 202  | Message accepted for delivery |
| 400  | Malformed request |
| 401  | Authentication failed |
| 402  | Plan limit exceeded |
| 403  | Access denied |
| 404  | Resource not found |
| 5xx  | Server error — retry the request |

## Status Callbacks (DLR)

When a `status_callback` URL is provided, Exotel sends delivery events via POST:

| Status Code | Event | Description |
|-------------|-------|-------------|
| `40001` | `EX_MESSAGE_SENT` | Message transmitted to the user's device |
| `40002` | `EX_MESSAGE_DELIVERED` | Message received by the device |
| `40003` | `EX_MESSAGE_SEEN` | User opened/read the message |
| `40004` | `EX_SYSTEM_ERROR` | Delivery failed due to system error |

### Callback Payload

```json
{
  "sid": "msg_abc123def456",
  "to": "+919888888888",
  "exo_status_code": "40002",
  "status": "EX_MESSAGE_DELIVERED",
  "timestamp": "2026-04-17T10:30:00.000Z",
  "custom_data": "order_12345"
}
```

## Incoming Messages (Webhook)

Configure an incoming webhook to receive messages from users. Supported content types:

| Content Type | Fields |
|-------------|--------|
| **Text** | `text` — the message body |
| **File** | `url`, `thumbnail_url`, `mime_type`, `size` |
| **Location** | `latitude`, `longitude`, `label` |
| **Suggested Reply** | `postback_data`, `text` |
| **Suggested Action** | `postback_data`, `action_type` |
